Guía de prompts para que otra IA construya tu sistema (costruir el sistema guiados por ia)

Hice 9 pasos. El primero (Paso 0) es el contexto que la IA necesita saber siempre. Los demás se pegan uno por uno, y no pasas al siguiente hasta que el anterior funcione pedazo de animal.

/////////    Cómo usar esta guía      ///////////
Abre un chat nuevo con la IA que vayas a usar. Una que genere código bien, como Claude, ChatGPT o Gemini.
Pega el Paso 0 primero y luego el Paso 1. En el mismo chat, sigue con los demás.
Prueba cada paso antes de continuar. Si algo falla, usa el prompt de errores del final.
Si el chat se llena o la IA se queda sin espacio, abre uno nuevo y usa el prompt de continuación del final.
Sube también el logo del instituto en el Paso 3.



----------Paso 0: Contexto del proyecto (pégalo siempre primero)
Actúa como desarrollador web senior. Voy a pedirte que construyas, por pasos, un sistema de control de pagos y notas para un instituto técnico superior de prótesis dental en Cochabamba, Bolivia ("Instituto Técnico Huntington California"). Es una DEMO con datos ficticios, de un solo administrador. Escribe en español (los textos de la interfaz también) y explícame todo con lenguaje claro, sin tecnicismos innecesarios.

ARQUITECTURA (obligatoria, sin cambiarla)
- Frontend: UN solo archivo index.html con HTML, CSS y JavaScript puro (sin frameworks, sin instalar nada). Debe verse bien en celular y computador.
- Backend: Google Apps Script publicado como aplicación web, que lee y escribe en un Google Sheets.
- Base de datos: Google Sheets con 3 pestañas: Estudiantes, Notas, Pagos. Las materias NO van en la hoja: van dentro del index.html.
- Publicación: el index.html se sube a Netlify (hosting estático gratis).
- Solo hay UN usuario administrador, protegido por una clave simple.

DATOS (nombres de columnas exactos, todo guardado como texto en la hoja)
- Estudiantes: id, nombre, documento, telefono, tutor, turno (Mañana/Tarde/Noche), semestre (1 a 6), estado (Activo/Egresado), fecha_cambio
- Notas: id, estudiante (id del estudiante), codigo (ej. "PRD 111"), fecha (AAAA-MM-DD), nota (0 a 100)
- Pagos: id, estudiante, gestion (año, ej. 2026), tipo (Semestre/Anual), semestre (1 a 6), fecha, anulado (SI/NO), motivo

PLAN DE ESTUDIOS (29 materias, 6 semestres; el código es "PRD " + número)
Semestre 1: 111 Anatomía y morfología dentaria; 112 Materiales dentales y laboratorio 1; 113 Tecnología dental; 114 Anatomía humana; 115 Química de materiales dentales; 116 Bioseguridad y ergonomía; 117 Computación.
Semestre 2: 121 Anatomía y topografía dentaria; 122 Prostodoncia total y laboratorio; 123 Prostodoncia parcial removible en resina y laboratorio; 124 Soporte básico de la vida; 125 Histología general y dental; 126 Inglés técnico.
Semestre 3: 211 Ortodoncia removible y laboratorio; 212 Oclusión 1 y laboratorio; 213 Materiales cosméticos; 214 Prostodoncia fija 1 y laboratorio; 215 Técnicas de investigación 1.
Semestre 4: 221 Prostodoncia parcial removible metálica 2 y laboratorio; 222 Ortodoncia fija y laboratorio; 223 Prostodoncia fija 2 y cerámica dental 1 y laboratorio; 224 Salud oral; 225 Deontología legal.
Semestre 5: 311 Biomateriales dentales 1 y laboratorio; 312 Prostodoncia removible 3, ataches y fresados y laboratorio; 313 Cerámica dental 2 y laboratorio; 314 Diseños y administración de laboratorio dental; 315 Patología bucal.
Semestre 6: 321 Pasantías en instituciones de convenio.

REGLAS DE NEGOCIO (no las cambies)
1. Pagos: el sistema NO maneja montos. Solo dice "Pagó" o "Debe".
2. Un estudiante "Pagó" si existe un pago con anulado="NO", de la gestión (año) actual, que cubra su semestre actual. Un pago tipo "Semestre" cubre solo ese semestre. Un pago tipo "Anual" cubre los dos semestres de ese año de carrera (1-2, 3-4, 5-6).
3. "Pagó/Debe" se CALCULA, nunca se guarda a mano.
4. Los pagos nunca se borran: se anulan con un motivo obligatorio.
5. Una materia está APROBADA si el estudiante tiene al menos una nota de 72 o más en ella. Con menos de 72 está reprobada. Puede haber varias notas por materia (si la repite).
6. Materias pendientes de un estudiante = materias de su semestre actual en las que no tiene ninguna nota de 72 o más.
7. Un estudiante pasa al siguiente semestre solo si no tiene materias pendientes. Si le falta alguna, se queda y solo repite esa.
8. Al aprobar PRD 321 en el semestre 6, el estudiante pasa a estado "Egresado" y sale de las listas activas, pero sus datos y notas se conservan.
9. Los egresados no aparecen en la lista de morosos.

--------------------------Paso 1: Script de Google (el backend)
Paso 1: Escribe el archivo Code.gs completo para Google Apps Script, ligado a una hoja de Google Sheets.

Requisitos:
- Una constante CLAVE al inicio (texto que yo cambiaré).
- Si las pestañas Estudiantes, Notas o Pagos no existen, créalas automáticamente con los encabezados exactos del Paso 0 y con todo el formato de columnas como texto plano (para que Sheets no convierta fechas ni números).
- doGet(e): recibe ?clave=...; si es incorrecta devuelve {"error":"clave"}; si es correcta devuelve JSON con las tres tablas: {Estudiantes:[...], Notas:[...], Pagos:[...]}, cada fila como objeto con todos sus valores como texto.
- doPost(e): recibe un JSON en el cuerpo (enviado como text/plain para evitar problemas de CORS) con: clave, accion, tabla, fila, id.
  * accion "add": agrega una fila nueva y genera un id único corto; devuelve el id.
  * accion "upd": busca la fila por id y actualiza solo los campos enviados.
  * accion "addmany": agrega varias filas a la vez (lista "filas"), para cargar datos de demo y para el cambio masivo de semestre.
  * accion "updmany": actualiza varias filas a la vez (lista de {id, fila}).
  * Usa LockService para evitar escrituras simultáneas.
- Ninguna acción borra filas.
- Todas las respuestas en JSON con ContentService.

Luego explícame paso a paso, para alguien sin experiencia: cómo crear la hoja de Google, abrir Extensiones > Apps Script, pegar el código, cambiar la CLAVE, publicar con Implementar > Nueva implementación > Aplicación web (ejecutar como "yo", acceso "cualquier persona"), autorizar los permisos y copiar la URL final. Dime también que cada vez que cambie el código debo crear una nueva versión de la implementación.

Prueba: abre la URL del script con ?clave=TU_CLAVE al final. Debes ver un texto JSON con las tres tablas vacías.
